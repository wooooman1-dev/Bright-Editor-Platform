`02_ARCHITECTURE_REDESIGN.md` D2 가 제안한 3분류를 시제품으로 구현해,

현행 원고 본문(1,484문장)으로도 돌렸지만 표본으로 쓸 수 없다 — 이미 스윕이

의미 있는 표본**이다.

### 시제품 판정 규칙

`external_fact` 는 3요소가 모두 있을 때만 성립한다.

| 요소 | 판정 |
| --- | --- |
| ① 수치값 + ② 단위 | 금액(`원`), 비율(`%`), 일자(`YYYY년 M월`), 조문(`제N조`), 기한·임계(`N일 이내`, `최대 N개월`) |
| ③ 귀속 주체 | 제도·급부·상품·기관·규범 지시어 (급여, 공제, 지원금, 연금, 세액, 통장, 예금, 적금, 대출, 요금제, 공단, 국세청, 약관, 상품설명서, 공고문, ~법 …) |

그 밖에:

- 값이 없으면 → `editorial_frame` (검증 대상 아님)
- `최근/지난 + 기간` 이고 주체가 없으면 → `editorial_frame`
- 값은 있는데 주체가 없고 독자 행동 안내면 → `editorial_frame`
- 값은 있는데 주체가 없고 안내도 아니면 → `unattributed_value` (회색지대)
- `정보 기준일:` / `최종 검토일:` → `publication_meta` (분류 제외)
- 계산 가정 고지가 있는 섹션 안 → `illustrative`

## 3. 시제품의 한계 — 구현 전에 고쳐야 할 3가지

측정을 하니 규칙 자체의 결함도 같이 드러났다. 정직하게 적는다.

### 3-1. 표 셀은 문장 단위로 판정할 수 없다

`unattributed_value` 6건 중 3건이 이것이다.

```
500,000원
80,000원
420,000원
```

표 셀 하나는 자기 주체를 담을 수 없다. 주체는 **행 라벨과 표 캡션**에 있다.
문장 단위 분류기에 셀을 그대로 넣으면 영원히 "주체 없는 값"이 된다.

→ 판정 단위를 `(셀, 행 라벨, 표 캡션)` 묶음으로 바꿔야 한다.

### 3-2. 임계 기간 + 주제어 조합에서 오탐이 난다

유일한 `external_fact` 판정이 오탐이었다.

> "예금 적금 선택 기준은 한 가지로 고정되지 않습니다. 보유 목돈이 있어도
> **1년 안에** 쓸 가능성이 크다면 장기간 묶는 선택보다 사용일과 **해지 조건**을
> 우선 점검해야 하고…"

`1년 안에`(임계 기간) + `예금/적금/해지 조건`(주제어)이 같은 문장에 있다는
이유로 사실 주장으로 잡혔다. 실제로는 독자 판단 기준 설명이다.

→ ③ 귀속 주체를 "문장 어딘가에 제도어가 있다"가 아니라 **"그 값을 서술하는
주체가 있다"** 로 좁혀야 한다. `X는 N이다` / `X를 N까지` 처럼 값이 주체의
술어인 구조를 요구한다.

### 3-3. 가정 예시가 illustrative 로 안 걸린다

> "예를 들어 이사 예정일이 **2027년 8월 20일**이고 현재 목돈이 있다면…"

`계산 예시 + 산출 + 대신하지 않` 3요소 고지가 있는 섹션만 `illustrative` 로
면제하는데, 이 문장은 그런 고지 없이 `예를 들어 … 라면` 가정문이다.

→ 가정문 구조(`예를 들어`/`가령` + `~라면`/`~다면`/`가정해`)를 별도로 인정한다.
단, 지난 세션이 경고한 대로 **`예시` 단어만으로는 면제하지 않는다** —
가정 표지와 조건절이 함께 있어야 한다.

## 6. 판정 결과 (2026-08-14, 사장님 확인)

### 판정 1 — 회색지대: **A. needs_review 로 보고만 한다**

`unattributed_value` 는 발행을 막지 않는다. 편집기에서 해당 블록을 지목하고
`PublishReadinessVerdict` 의 `advisory` 로 올린다. Review First·Draft Only 가
켜져 있으므로 사람이 반드시 한 번 본다.

### 판정 2 — 기준 강도: **현행 제안대로 진행 (더 엄격하게 하지 않음)**

사장님이 판단을 위임하셔서 근거를 적는다.

**1. AdSense 는 문장별 출처를 요구하지 않는다.**
공식 자격 요건은 "high-quality, original content"이고, 개별 수치의 인용·출처
검증을 요구하는 조항은 없다. `14_ADSENSE_APPROVAL_CONTENT_POLICY.md` 의
출처 요구는 우리 내부 정책이며 AdSense 기준보다 엄격하다.

**2. 엄격함이 오히려 거절 사유를 만들고 있었다.**
블로그 거절 사유 1위는 low value content — 얇고 불완전한 콘텐츠다. 스윕이
만들어낸 결과물이 정확히 그 상태다:

- content-msn722jz: 본문 1,157자, 문단 7개, 비교 표 빈칸
- 최근 15편 1,499문장 중 금액·비율·날짜가 남은 문장 6개
- 생활금융 글에 숫자가 없음

즉 지금까지의 엄격함은 승인을 돕는 게 아니라 **거절 사유를 직접 생산**하고 있었다.
81% 를 검증 대상에서 빼는 것은 완화가 아니라 **오분류 교정**이다 — 값 없는
조건어는 애초에 사실 주장이 아니었다.

**3. 다만 내부 정책은 유지할 값어치가 있다.**
생활금융은 YMYL 주제이고, 값이 있는 주장(지원금·세율·금리·신청 기간)에 출처와
정보 기준일을 붙이는 것은 검색 품질 관점에서 유리하다. 정책
`14_...:232` 가 차단 대상으로 지목한 것도 정확히 그 넷이다.

**따라서 게이트를 푸는 것보다 Phase 2 가 더 중요하다.** 지금은 "출처 없으면
지운다"만 있고 "출처를 쓰게 한다"가 없다. Phase 1 직후 Phase 2 를 최우선으로
붙인다. 게이트만 풀고 Phase 2 를 미루면 숫자 없는 글이 숫자 있는 글로 바뀌기만
하고 출처는 여전히 없다.

> 승인은 누구도 보장할 수 없다. 위 판단은 정책 문서와 실측에 근거한 것이며,
> 심사 결과를 예측하지 않는다.

### 진행 순서 조정

기존 Phase 1 → 2 → 3 순서를 유지하되, **Phase 2 를 Phase 3 보다 확실히 앞에**
둔다. 게이트 통합(Phase 3)은 출처가 본문에 실제로 쓰이기 시작한 뒤에 해야
