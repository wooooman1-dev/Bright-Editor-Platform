## 3. 남은 문제 2가지

### 3-1. 10자 부족으로 발행이 막힌다 (Phase 3 대상)

```
품질 100 / approved=false / blocked
CONTENT_SECTION_PROSE_INSUFFICIENT
  섹션: 대출 실행 전 비교표를 만드는 순서
  minimum 250 / actual 240
```

5,074자 원고가 **한 섹션의 10자 부족**으로 `in_review` 에 묶였다.
Claim 게이트로 막힌 게 아니라 구조 진단이다 — 교착은 아니지만, 사용자가
무엇을 어떻게 고쳐야 하는지 화면이 말해 주지 않는다.

D-039 의 "모든 차단에는 실행 가능한 해결 경로가 있어야 한다"가 정확히 이 경우를
위한 규칙이다. Phase 3 `PublishReadinessVerdict` 가
`{ kind: "edit_body", blockId, hint: "이 섹션에 10자 이상 추가" }` 를 붙여야 한다.

### 3-2. 계산 예시 고지가 면제 기준에 못 미친다 (Phase 2 대상)

표의 금액 11건이 `external_fact` 로 잡혔다. 그런데 이 표는 실제로 계산 예시다:

> "아래 표는 대출원금 1억원, 연 4.8%, 3년, 매월 납부라는 동일한 가정을 둔
> 계산 예시입니다."

`illustrative` 면제는 3요소를 요구한다 — (계산 예시\|가정) AND (산출\|계산) AND
(대신하지 않\|반영하지 않\|다를 수 있). 위 문장은 앞의 둘만 만족한다.
**"실제 계약 청구액을 대신하지 않습니다" 같은 한계 고지가 빠졌다.**

기준을 낮출 문제가 아니라 **생성이 고지를 완전하게 쓰게 만들 문제**다.
Phase 2 프롬프트 작업에 이 항목을 포함한다. 지난 세션이 경계한 대로
`예시` 단어만으로 면제하면 근거 없는 숫자가 그대로 통과한다.

## 6. 이 과정에서 잡은 것 2가지

### 6-1. 내가 만든 회귀 — 서버 전용 모듈이 클라이언트 번들로 끌려갔다

`core/ai/index.ts` 에 `withCalculationExampleDisclosureContract` 를 **값으로**
export 했더니 개발 서버가 죽었다.

```
You're importing a module that depends on "server-only".
./core/approval/ApprovalSourceDocumentServerAdapter.ts
```

원래 이 index 는 AIWorkflow 에서 **타입만** export 하고 있었다. 값 export 하나가
AIWorkflow → `../approval` → 서버 전용 어댑터를 클라이언트 번들로 끌어들였다.

**tsc·eslint·vitest 는 이걸 못 잡는다.** 번들러 경계 문제라 앱을 실제로 띄워야
드러난다. 원고 1편 생성이 완료 기준이어야 하는 이유가 이것이다.

되돌렸다. 테스트는 `core/ai/AIWorkflow` 에서 직접 import 한다.

### 6-2. Source Preflight 실패에 진단이 남지 않는다 (미수정)

`content-mst2r5wl-eadjnz` "전월세 전환율 계산 방법" 생성이 preflight 에서 막혔다.

```
wf: failed / retryFrom: generation
error: "사용 가능한 공식 출처를 확인하지 못했습니다."
approvalSourcePreflightDiagnostic: {} ← 비어 있음
```

지난 세션이 월세 세액공제 건에서 "이 진단을 남기는 구조 자체는 잘 작동했다"고
기록했는데, 이 경로에서는 **아무것도 저장되지 않는다.** 어느 Claim 이 왜 막혔는지
알 수 없고, 사용자에게는 해결 경로가 없는 실패만 남는다.

D-039 의 "모든 차단에는 실행 가능한 해결 경로가 있어야 한다" 위반이다.
**Phase 3 의 첫 대상 목록에 추가한다.**
