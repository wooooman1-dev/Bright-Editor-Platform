# Bright Studio AdSense Site Readiness Automation

Version: 1.0

Status: Accepted

Applies to: Tistory and future platforms using `adsense_approval`

Last updated: 2026-07-28

---

## 1. Purpose

이 문서는 `17_ADSENSE_APPROVAL_READINESS_BLUEPRINT.md`의 사이트 준비 항목과 실행 시점을 구체화한다.

Bright Studio는 외부 AdSense 승인을 보장하지 않는다. 다만 공식 정책상 확인 가능한 필수 항목과 운영상 권장 항목을 구분하고, 같은 원고와 같은 사이트를 불필요하게 반복 검사하지 않는다.

---

## 2. Site Check Classification

사이트 준비 검사는 다음 두 등급을 사용한다.

```text
required
recommended
```

### Required

다음 항목은 승인 준비 상태를 통과하기 위해 필요하다.

- 공개 사이트 정상 접근
- HTTPS
- 주제 정체성
- 메뉴와 내부 탐색
- 공개 카테고리
- 모바일 viewport
- 개인정보처리방침 공개 경로
- 공사 중·placeholder 없음
- 표본 내부 링크 정상

개인정보처리방침에는 최소한 Google을 포함한 제3자 광고사업자의 쿠키 사용, 방문 이력에 기반한 광고 제공 가능성, 맞춤 광고 해제 경로가 안내되어야 한다.

### Recommended

다음 항목은 신뢰성과 운영 투명성을 높이는 권장 사항이다.

- 사이트 또는 블로그 소개
- 문의 또는 연락 경로

권장 항목이 없다는 이유만으로 다른 필수 항목을 모두 통과한 사이트를 `needs_review`로 유지하지 않는다. 대신 화면에 권장 보완 사항으로 표시한다.

---

## 3. Automatic Readiness Run

승인 준비 검사는 다음 조건에서 자동으로 한 번 실행한다.

```text
Content Purpose = adsense_approval
+ 현재 Revision의 standard 품질 승인 완료
+ 현재 Revision에 대한 승인 준비 검사 기록 없음
```

검사 결과에는 현재 `contentRevisionId`를 저장한다.

같은 Revision에 이미 검사 기록이 있으면 자동으로 다시 실행하지 않는다. 성공·실패 여부와 관계없이 사용자가 명시적으로 `다시 검사`를 누르기 전까지 저장된 진단을 보여준다.

원고가 수정되어 Revision이 변경되고, 새 Revision의 standard 품질 검토가 완료되면 자동 검사를 다시 한 번 실행한다.

이 흐름은 AI 호출을 추가하지 않는다.

---

## 4. Manual Recheck

첫 검사 이후 버튼 문구는 다음처럼 표시한다.

```text
승인 준비 다시 검사
```

수동 재검사는 다음 상황에 사용한다.

- 개인정보처리방침 또는 메뉴를 추가한 뒤
- 공식 출처 접근 상태가 바뀐 뒤
- 사용자가 현재 공개 상태를 즉시 다시 확인하려는 경우

---

## 5. Evidence Diagnostics

공식 출처 Gate는 채택된 검증 출처가 한 개 이상 있고 원고 사실과 일치하면 통과할 수 있다.

다음 후보는 진단 기록으로 보존하지만 통과한 Gate를 다시 막지 않는다.

- canonical 중복 후보
- 채택되지 않은 403 후보
- 채택되지 않은 429 후보
- 다른 검증 완료 출처가 있는 상태의 보조 후보 실패

기본 화면에서는 채택된 출처를 우선 표시하고 전체 실패 후보는 상세 진단에서 확인한다.

## 6. Tistory Trust Pages

Tistory는 고정 `페이지` 기능을 제공한다. 현재 Bright Studio의 승인된 Playwright Workflow는 게시글 임시저장까지만 지원하므로, 신뢰 페이지를 임의 자동 생성하거나 공개하지 않는다.

운영자는 다음 페이지를 Tistory 관리자에서 직접 추가하고 메뉴에 연결한다.

### Required Page

```text
개인정보처리방침
```

### Recommended Page

```text
블로그 소개 및 문의
```

페이지 생성 후 공개 첫 화면의 상단 또는 하단 메뉴에서 접근 가능해야 한다.

## 7. 개인정보처리방침 기본 문안

아래 문안은 Tistory 블로그와 Google AdSense 사용을 전제로 한 운영 템플릿이다. 블로그의 실제 데이터 처리 방식이 달라지면 공개 전에 수정해야 한다.

```text
개인정보처리방침

본 블로그는 방문자의 개인정보를 중요하게 생각하며, 관련 법령과 서비스 정책을 준수하기 위해 다음과 같이 개인정보 및 쿠키 처리 방침을 안내합니다.

1. 직접 수집하는 개인정보
본 블로그는 별도의 회원가입, 결제 또는 개인정보 입력 양식을 운영하지 않습니다. 댓글과 방명록을 이용할 경우 닉네임, 작성 내용 및 서비스 운영에 필요한 기술 정보가 Tistory 운영 정책에 따라 처리될 수 있습니다. 민감한 개인정보는 댓글이나 공개 방명록에 남기지 마세요.

2. 쿠키와 광고
본 블로그는 Google AdSense를 포함한 제3자 광고 서비스를 사용할 수 있습니다. Google과 제3자 광고사업자는 쿠키를 사용하여 사용자의 본 블로그 또는 다른 웹사이트 방문 기록을 바탕으로 광고를 게재할 수 있습니다.

Google의 광고 쿠키 사용으로 Google과 파트너는 사용자의 본 블로그 및 다른 인터넷 사이트 방문 기록을 기반으로 맞춤 광고를 제공할 수 있습니다.

사용자는 Google 광고 설정에서 맞춤 광고를 사용 중지할 수 있습니다.

3. 접속 기록과 외부 서비스
블로그 운영, 보안, 통계 및 광고 제공 과정에서 IP 주소, 브라우저 정보, 방문 일시, 이용 기록과 같은 기술 정보가 Tistory, Google 또는 관련 서비스 제공자에 의해 처리될 수 있습니다. 각 외부 서비스의 데이터 처리는 해당 서비스의 개인정보처리방침을 따릅니다.

4. 외부 링크
본 블로그에는 외부 사이트로 연결되는 링크가 포함될 수 있습니다. 외부 사이트의 개인정보 처리와 콘텐츠에 대해서는 해당 사이트의 정책이 적용됩니다.

5. 문의
개인정보 및 운영 관련 문의는 본 블로그 방명록의 비밀글 기능을 이용해 주세요. 공개 댓글이나 공개 방명록에는 개인정보를 작성하지 마세요.

6. 변경 안내
본 방침은 관련 법령, 플랫폼 정책 또는 블로그 운영 방식의 변경에 따라 수정될 수 있습니다. 중요한 변경이 있는 경우 이 페이지를 통해 안내합니다.

시행일: 2026년 7월 28일
최종 수정일: 2026년 7월 28일
```

## 8. 비바레인 소개 및 문의 기본 문안

```text
비바레인 소개 및 문의

비바레인은 미술 초보 독자가 서양미술의 화가와 작품을 단순 암기가 아니라 시대적 배경, 화면의 시각적 특징, 감상 포인트와 확인 가능한 공식 자료를 통해 이해하도록 돕는 미술 감상 가이드입니다.

본문의 작품명, 작가명, 제작 시기, 재료, 크기와 소장처처럼 확인 가능한 정보는 공식 미술관·박물관·재단·공공 아카이브 자료를 우선 확인합니다. 감상과 해석은 확인된 사실과 구분해 설명하며, 특정 해석을 유일한 정답처럼 단정하지 않습니다.

내용 오류, 출처 수정 요청, 저작권 관련 문의 또는 블로그 운영 문의는 방명록의 비밀글 기능을 이용해 주세요. 공개 글에는 이메일, 전화번호 등 개인정보를 남기지 마세요.
```

## 9. 밝은건강 소개 및 문의 기본 문안

```text
밝은건강 소개 및 문의

밝은건강은 일상에서 실천할 수 있는 건강정보와 운동 방법을 이해하기 쉽게 정리하는 생활 건강 가이드입니다.

건강 콘텐츠는 일반적인 정보 제공을 목적으로 하며 개인의 진단이나 치료를 대신하지 않습니다. 증상이 지속되거나 심해지는 경우에는 의료기관 또는 자격을 갖춘 전문가의 상담이 우선입니다. 제도, 비용, 지원 대상과 같이 변경될 수 있는 정보는 공식 기관 자료와 확인 날짜를 함께 안내합니다.

내용 오류, 수정 요청, 출처 또는 블로그 운영 문의는 방명록의 비밀글 기능을 이용해 주세요. 공개 글에는 건강 상태나 연락처 등 민감한 개인정보를 남기지 마세요.
```

## 10. Completion Boundary

이 변경은 다음을 확인한 뒤 완료로 선언한다.

- required/recommended 분류 테스트
- 소개·문의만 없을 때 사이트 Gate 통과
- 개인정보처리방침이 없을 때 `needs_review`
- 현재 Revision 자동 검사 1회
- 같은 Revision 자동 재실행 없음
- Revision 변경 후 standard 재승인 시 자동 재검사
- 저장된 출처 상세 진단 복원
- lint, typecheck, tests, build
- 실제 브라우저 검증
